# 项目与完成核验（导出仅按明确要求）

默认先完成全部可用来源的导入、初步校色、逐帧复核与修复，保存项目并提示用户检查、打分。等用户检查后说明导出要求，再接续导出。用户说“不用导出”时不打开导出面板、不生成成片，也不把未导出列为失败。以下导出章节只有用户明确要求时才适用。

## 保存项目

通过 App 的 Command-S / Save As 保存 `.cineon26` 项目到本次输出目录，核对实际位置与名称。已命名项目后续自动保存，但结束前仍检查保存错误和正在写入状态。

项目保存编辑、组织和预览，不包含外部 RAW/3F。交付时保留来源路径映射，不能声称单独一个项目文件即可离线重建全部照片。不关闭用户仍在使用的会话；需要重开验收时先确认无正在运行任务，并用已保存的本次项目操作。

在 `processing-log.json` 中记每张照片的来源/slot/RGB 组、Film/Frame 声明及依据、实际处理状态、修复记录、导出路径和错误。明确区分用户给定、直接可读证据与尚未确认的推断。日志是恢复依据，不代替实际项目状态。

## 交给用户检查、打分

确认本次队列已结束、可检查照片有当前有效结果、项目已保存。核对全部输入的去向；有未解决项时交付已完成部分并列出具体范围，不能将抽样或部分成功称为整批完成。保留用户已有评分和编辑，不自行给照片打分或替用户决定取舍。

让本次项目保持可查看状态，明确告知：“初步处理已完成，项目已保存，你可以开始检查和打分了。”同时给出可检查数量、需要注意的例外和项目位置。日志将任务阶段记为 `awaiting_user_review`；这是第一段的正常完成状态。交接后结束本轮操作，等待用户下一条消息，不继续调色、改评分或发起导出，也不用此时追问全部导出参数。

## 接续用户检查后的导出

用户回来后，核对并继续同一项目，以 App 当前评分、选择、调色和裁切为准；日志只帮助定位，不能把旧记录恢复到用户刚审过的项目。用户只说检查完成时，不自行导出；用户明确给出导出指令且信息足够时直接执行，不再重复确认是否导出。只补问会影响结果的缺失信息。

按用户自然语言确定范围，例如“4 星及以上”“只要 5 星”“我选中的这些”或指定分组。核对评分筛选的等于/至少条件、实际目标和数量；不要把所有已处理照片默认当成用户选片结果。保留用户已审定的编辑，仅处理实际阻碍导出的状态问题，不为导出而重跑整批 Auto。

## 发起导出

1. 核对所有目标都有当前成功结果：源文件可读、对应 ICC 可用、没有未确认分帧、几何待复核或上游改动。跳过项也要计数与记录。
2. Shift-Command-D 打开导出面板。第一次不要直接 Command-D 沿用未知的历史目录和设置。
3. 明确选择用户指定范围。按评分时可用实际界面的 By Score 并核对阈值；若它会包含本次范围之外的照片，则先选中目标，再用 Selected Image(s)。指定组或选中照片也先核对实际成员，避免同一照片在多组中被重复计数。只有用户要求全导出且全部目标都在授权范围内才用 All Images。检查面板实际可导出数和排除项。
4. 根据用户要求设置 Format、Size、Color Space、Area 和 Metadata，以及当前格式提供的质量/位深等选项。已有明确偏好直接沿用；其余未指定项可采用原始尺寸、16-bit TIFF、ProPhoto RGB 等合适默认值，记录实际设置。区域必须结合用户的当前裁切与去边/保留片边要求。PNG/JPG 会默认转向 sRGB，必须读取最终值。
5. 有输出裁切需求时逐图确认 Crop 后选 Cropped Area。未建立裁切的照片即使选 Cropped Area 也会导出完整画布，不能靠此选项自动去片边。
6. 选择任务输出目录再开始导出。导出时设置和目标被冻结；过程中修改照片不会进入这次导出。需要新效果时等待修改完成后为相应照片重新导出，并记录新的版本。

原片数、生成照片数与导出数分开统计。例如一条 3F 可生成多帧；三张 RGB 可生成一张；四曝光序列可以有合成图和独立白光图。总量核对以实际分帧/分组映射为准，不以文件名数量推断成功率。

## 核验成片

导出完成提示之后仍检查：

- 对照 App 的逐项结果和实际输出路径核对成功、失败、跳过数；不把输出目录既有文件算进本轮。
- 所有成功项有可读的非空文件；核对像素尺寸、格式、位深与嵌入色彩空间是否符合请求。使用当前环境已有的只读图像检查器；若不能读取某项属性，明确标为未核验，不能仅凭导出设置声称文件符合。
- 用色彩管理一致的方式查看每张缩览，检查正负关系、方向、明显错帧、裁切和重影；所有人工修复或异常项再放大检查。不同查看器的色彩管理差异不能直接作为科学色差结论。
- 再核对项目保存状态和原片 SHA-256。只有前后字节哈希相同才报告原片逐字节未变。

成功输出不代表科学色彩校准。记录实际看到的外观问题和诊断，不承诺无法验证的准确度。

## 中断与重跑

先核对项目、日志和已有成片，避免重复导入。当前 App 的 Resume 可能重试整个冻结导出批次，并给重名输出生成安全副本，不是逐张 checkpoint。

有明确成功映射时，只选择尚未导出的可用照片发起新导出；使用 Only Unexported 前确认它针对当前格式和当前有效结果。需要精确恢复原冻结设置时再使用 Resume，随后识别并记录副本。不要删除原有成片来凑数量，也不要用覆盖来“修复”重复项。

失败目标写明原因和下一步：需提供胶卷型号/正确 ICC、找回源文件、补拍、重拍或等待 App 修复。其他成功图可以正常交付，整体状态应写“部分完成”。

## 验证边界

实际核对导入、处理、保存和用户要求的导出结果。只完成抽样时注明范围；未运行的分支标为未验证。已有真实 App 实测的范围见仓库 README。不要读取或索要开发源码来证明 GUI 操作成功。
