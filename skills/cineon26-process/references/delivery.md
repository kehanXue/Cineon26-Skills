# 保存、交接与按要求导出

默认先完成全部可用来源的导入、初步校色、逐帧复核与修复，保存项目并交给用户检查打分。用户说“不用导出”时，不打开导出面板、不生成成片，也不把未导出列为失败。

## 保存项目与快照

Command-S / Save As 保存 `.cineon26` 到任务输出目录。核对实际路径、名称、保存错误和落盘结果；已命名项目后续自动保存，结束前仍检查。项目保留编辑、评分、分组、快照和小预览，但不包含外部 RAW、DNG、TIFF、3F 或扫描输入 ICC。不要声称单独的项目就能离线重建全部照片。

需要长期保留一个编辑版本时，用 S / Save Snapshot，或照片右键“保存快照”。右键操作针对被右击照片，不必改变当前图。快照预览仅用于浏览比较；Restore Snapshot 才应用历史状态并可能恢复完整画面。Esc 退出比较回到当前编辑。不要在历史预览状态下继续修框或导出，先确认当前状态。

Command-Z / Shift-Command-Z 是会话内撤销/重做，不代替持久快照。照片右键“在 Finder 中显示”用于核对原片位置；不要移动或修改原件。

需要重开核验时，先等队列结束并保存本次项目。打开旧项目应保留手调、裁切、评分与快照；按 [recovery.md](recovery.md) 处理访问、缺失、ICC 和缓存问题，不因重开就重新 Auto。保护用户原工程；测试新版本时使用独立副本。

## 交给用户检查、打分

核对队列结束、当前有效结果、项目已保存，以及全部输入的去向。部分成功要列出具体范围，不能把抽样称为整批完成。纯片基片段、不可处理来源及仍需用户判断的项分别说明；不自行评分或删除取舍。

让项目保持可查看，明确提示：“初步处理已完成，项目已保存，可以开始检查和打分了。”给出项目位置、可检查范围和必要例外，日志记为 `awaiting_user_review`，然后结束本轮。此时无需提前问全部导出参数。

## 接续导出

收到明确导出要求后，从同一项目读取**最新**评分、调色、裁切及组织。旧日志只辅助定位，不能覆盖用户刚完成的编辑。用户只说检查好了，不代表已要求导出；明确要求且信息足够就执行，不重复征求批准。

按自然语言确定范围，如“所有有星标的，以及 4×5 分组”。核对评分的等于/至少条件，合并重复引用；同一照片可能出现在多个组。只缺少会影响成片的信息时补问。保留用户编辑，不为了导出重新导入或重跑整批 Auto。

## 导出设置

1. 用 Shift-Command-D 打开面板，先查看范围、可导出数量、跳过原因。Command-D 会沿用这个项目上次提交的设置和目标，未知时不用它直接启动。
2. 明确 Selected Image(s)、By Score 或 All Images。评分范围可能跨组；指定组合范围时先选中目标，再按选区导出。只在用户要求全项目时用 All。
3. 按要求设置 Format、Size、Color Space、Area、Metadata、质量/位深和目标目录。未指定时可采用原尺寸、16-bit TIFF、ProPhoto RGB，记录实际选择。切换格式会改变默认色彩空间，必须再读最终值。
4. 保留用户裁切时选 Cropped Area；Original 输出完整画面，忽略构图裁切但保留项目中的裁切设置。未建立裁切或 Reset Crop 后，Cropped Area 仍是完整画面，不会自动采用 Active Area 去边。
5. 源文件、ICC 或缓存提示按当前操作恢复；App 已验证完整缓存并允许导出时可以继续。不能仅凭一个来源提示阻止全部导出，也不能用旧缩略图证明全分辨率可用。
6. 核对输出位置后开始。提交时固定本次目标、设置和照片编辑；后续改图不会进入这次导出。需要新效果时等编辑完成，再导出相应照片。

| 输出需求 | 120 中的选择与核对 |
| --- | --- |
| SDR TIFF | 16-bit TIFF，可选 ProPhoto RGB、Adobe RGB (1998)、Display P3、sRGB |
| SDR PNG / JPG | PNG 8/16-bit、JPG 质量 1–5；切换默认 sRGB，按要求核对最终值 |
| SDR HEIC | HEIC (HDR) 中关闭 Preserve HDR，质量 1–5；按实际界面选择 Display P3 或 sRGB |
| HDR HEIC | 目标照片已启用 HDR Mode，再选 HEIC (HDR) 并开启 Preserve HDR；混合范围中其他照片仍为 SDR |
| 尺寸 | Original；4K 长边不超过 3840；1080P 长边不超过 1920 |

**120 的 HDR 保留仅在 HEIC (HDR) 提供；TIFF、PNG、JPG 输出 SDR。** 不沿用早期 JPG/PNG HDR 说明。Display P3 是色彩空间，选择它不等于开启 HDR。HDR 开关在照片中独立于 Post-processing；不要只开后期总开关就认为 HDR 已启用。

没有目标启用 HDR 时，Preserve HDR 不可用；若用户要求 HDR，先对其指定目标开启 HDR 并检查画面。照片本身没有可用 HDR 亮度余量时可能输出 SDR；不要与当前屏幕的显示限制混淆。黑白负片也可在处理后开启 HDR。屏幕无 HDR 能力或暂时缺少额外亮度时，120 会显示简短提示；这不关闭照片的 HDR 状态，也不等于无法保留 HDR 导出。不要擅自调整用户屏幕亮度。macOS 15 及以上与 macOS 14 的 HEIC HDR 表现及 SDR 回退存在差异，查看软件也可能仅显示 SDR；不能用普通截图或文件后缀证明 HDR 效果。

## 核验成片

- 对照 App 逐项结果与实际输出，核对成功、失败、跳过数。不要把目录旧文件计为本次输出。源文件数、分帧照片数和导出数分别统计。
- 成功项应存在、非空且可读；只读检查实际像素尺寸、格式、位深和嵌入色彩空间。HDR 输出还需能识别相应信息的工具或兼容查看器；普通读取可能只报告 HEIC 的 8 位 SDR 底图，不能据此判定没有 HDR。结合 HDR 解码或有效 HDR 元数据核验，无法核验的属性明确说明，不根据面板选择断言文件符合。
- 用一致的色彩管理查看缩览，检查正负关系、方向、截断、裁切和重影；异常及手修项放大看。不同查看器的显示差异不是科学色差结论。
- 再保存项目、更新日志，并核对源文件哈希。前后相同时才报告原片逐字节未变。

## 中断与继续

先核对项目、当前有效结果、日志和已有输出。Resume 可能重试整个冻结批次，对已存在文件生成安全的新名称，不能假设逐张断点续传。

已知成功映射时，优先只选择未完成目标发起新导出；Only Unexported 要核对当前格式与当前编辑。需要原冻结设置时才用 Resume，随后辨认副本，不删除旧成片来凑数量。

保留具体错误及下一步，例如恢复原片访问、找回原件、选择正确 ICC、补拍或等待 App 修复。其他成功结果正常交付，整体称为部分完成。实际没有执行的分支如实注明，不用开发源码或内部测试记录冒充 GUI 验证。
