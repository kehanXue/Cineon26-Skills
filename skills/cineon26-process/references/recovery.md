# 失败诊断与人工修复

## 先确定失败发生在哪一层

读取卡片的失败详情，记录来源、原文错误、发生步骤及当前状态。保持成功照片的结果，不将整批标为失败。按以下层级定位：

| 现场状态 | 处理方式 |
| --- | --- |
| Import / Auto 灰色 | 先检查编辑权益、弹窗、当前选择、正在处理状态、3F ICC、未确认分帧、几何待复核；不要仅凭按钮灰色重装 App |
| 源文件缺失 | 用正常 `Locate File / Folder` 定位原文件，核对身份；来源内容已变时找回原件或明确重新导入，不能把旧预览当原片 |
| 不支持/解码失败 | 确认扩展名、真实格式和来源完整性；保留该文件并继续其他组，不改后缀或转换后冒充原 RAW |
| Film / Frame Format 声明错误 | 用 Film & Frame 面板修改正确声明，再重新 Auto；画幅或负片/反转片切换会使旧结果失效 |
| 3F 扫描输入 ICC 缺失或失效 | 按 [workflows.md](workflows.md) 的 ICC 恢复流程，从用户指定的 Flextight-X5-ICC 仓库下载所需文件，在 App 设置导入并确认可用，再重试受影响的照片 |
| 3F 条带尚待复核 | 完成真实分帧检查，确认后再逐帧 Auto；不通过改项目文件绕过确认 |
| 画面/片基不可靠或两者重叠 | 用下述几何编辑修复；裁切工具不能修复这类测量问题 |
| RGB 组合失败 | 核对该组三张的画面、通道次序、曝光、几何和匹配平场；修复后只重试这一组 |
| 已有处理结果不兼容 | 在当前版本允许时，确认来源、分帧和已保存几何后显式 Auto 重建；相同不兼容错误持续出现则保留项目、记录版本及错误，不清空缓存或手改项目 |
| RAW 成片明显偏色但流程成功 | 核对类型、片基和画框后，启用 Color Balance 并复查，见“RAW 偏色：Color Balance”；不限于偏紫，不以换胶卷或挪片基做调色 |
| 成片偏亮或其他外观问题但流程成功 | 先排除类型、片基、边框和拍摄问题，再按用户要求使用相应 GUI 编辑控件 |
| 导出时提示 `artifact manifest is missing` | 按下节尝试恢复全分辨率预览，保留用户评分和编辑；不要为补缓存重新 Auto Color |
| 导出失败 | 读取逐项原因，检查目标路径、空间、源文件和当前结果；继续可用项，参见 [delivery.md](delivery.md) |

## 导出时全分辨率缓存缺失

已实测的症状是导出报告 `artifact manifest is missing`，而照片仍有预览和已保存的编辑。只在源文件和 ICC 可用、当前结果没有上游改动或几何待复核时尝试此恢复；普通路径/空间错误不走这个分支。

1. 记录失败目标、实际错误、导出设置及已有成功输出。保留最新评分、Film/Frame、方向、几何、调色和裁切，通过实际界面核对，不直接修改项目文件。
2. 在 App 中选中受影响照片，使用 `View → Actual Size (100%)`，让当前版本尝试加载全分辨率预览。等待实际图像完成；缩放值变成 100% 本身不证明缓存已恢复。
3. 核对用户编辑和评分未变，然后只重试受影响的导出目标，并按 [delivery.md](delivery.md) 核验落盘结果。大批次缓存可能再次被淘汰，优先恢复后及时导出当前小批目标。
4. 同一目标恢复后仍报相同错误时，记录阻碍并继续其他可用项。不要反复重建整批、清空全部缓存、直接写缓存/项目文件，或把重新 Auto Color 当成保留原编辑的缓存恢复。

这是已验证的 GUI 恢复办法，是否可用以现场 App 版本和结果为准；不声称导出器会自动恢复。已有处理结果不兼容时另行判断，不能用旧预览掩盖失败。

## RAW 偏色：Color Balance

初步校色时，对明显偏色的 RAW 可启用 Color Balance；用户已有明确设置要求时优先遵照。确认当前照片及选择范围、Film、Active Area 和负片 Film Base 正确，再开启该照片的 Color Balance。没有手动中性参考时采用 App 的 Auto；已有用户设置的参考时保留，不静默清除。读取实际 Strength，不把某张照片的参数套到整批。

等待 App 完成更新，确认开关已开启、控件恢复可用，在 Fit 与 100% 下复查。仅启用 Color Balance 不要求额外重跑顶部 Auto Color；仍有上游待更新提示时才按对应原因重建。记录开启前后的偏色变化并保存项目，明显恶化时恢复原设置并保留异常。当前分支没有可用的 Color Balance 控件时，记录实际限制。不要将场景原有的日落或彩色灯光一律消成中性色；进一步手动参考或其他调色按用户要求执行。

用户确认某张照片的色调属于场景本身时，保留其处理设置，记录该照片的场景色彩已确认，并撤销对应的颜色待复核标记；不要将此判断扩展到同型号的其他照片。仅因当前分支没有 Color Balance 控件，不应把已确认的正常场景色彩记为处理失败。

## 几何修复：G

必须分清三个对象：

- **Active Area**：绿色虚线的有效画面边界，影响自动估计。
- **Film Base**：橙色虚线的负片片基取样区域，影响负片处理。
- **Crop**：白色裁切工具，只影响最终构图和 Cropped Area 导出。

修复方法：

1. 清除无关复选选择，选中失败照片并看清文件名/帧号。退出历史 Snapshot 预览，确认处于当前编辑状态。
2. 用 `G` 或 Show / Hide Geometry Results 查看完整源画面；读取当前截图。反转片只编辑 Active Area，不寻找或补画负片 Film Base。
3. 绿色 Active Area 沿真实曝光画面的四边放置，排除片边、齿孔、夹具与相邻帧；保留实际画面，允许顺着透视调整四角。不要凭画幅预设制造不存在的边界。
4. 对负片，橙色 Film Base 放在该帧/slot 内可见、均匀、未曝光的真实胶片材料上，避开画面、文字、齿孔背光、黑色夹具、反光和脏点；与 Active Area 分离。不能从相邻 slot 借片基，也不能把白光孔洞当成片基。
5. 拖动角、边或内部达到有效位置后松手，查看新截图确认改到了预期对象。细片基的中央用于平移，框外侧用于调边；先放大再精细调整。尊重 App 的最小区域和有效性限制。
6. 发生误拖立即 Command-Z 并核对结果。Geometry Reset 回到最近成功几何或首次复核起点；不是取消所有任务的通用按钮。
7. 回到 Auto Color。通常几何复核需要一次实际、有效的修改才可重试；仅开关 overlay、缩放、切图或修改 Crop 不算。不要无意义地挪一个像素只为解锁按钮。
8. 等待重建结束，重新检查 Active Area、Film Base、成片与当前可导出状态。旧画面仍显示时，仍要确认没有 `review`、upstream changes 或失败状态。

完整源画面与显示缩放不是原始测量坐标。使用当前截图操控界面，让 App 保存坐标；不要直接改工程数据。没有可靠片基时保留失败原因，用户可能需要重新取景/翻拍。

## RGB 失败组

从失败组任一张进入，检查 R、G、B 三张。画布直接提供几何时，沿用正常工具；同组三张共享几何，修改其中一张后切换另外两张确认均适用。其余独立帧不会因此获得相同画框。

几何有效修改后使用通常的顶部 Auto Color，仅重试这组三张。不要寻找不存在的独立“RGB 重试”按钮。仅更改平场时，Auto 可重新自动检测，但不把未编辑建议标作人工确认。

配准失败先确认三张确为同一帧、没有次序错位或大幅移动。确实过曝、丢通道、跨帧或对齐无法成立时，保留原片并记录需重拍；不能承诺移动 Film Base 会修复所有配准失败。

## 构图裁切：C

只在已有当前有效处理结果后使用。按用户要求打开 `C`，选择 Film Ratio、Free 或当前界面支持的比例，移动/缩放/调平。去边时检查四周，不切进有效画面；保留片边时用 Free 按实际内容扩框。

裁切实时生效；C、Enter、Done、Esc 都只是收起工具，**Esc 不撤销裁切**。取消误操作用 Command-Z；`Reset Crop` 恢复完整画面并清除裁切旋转。G 显示完整源画面时看见片边，不等于裁切丢失。

要输出裁切效果，导出 Area 必须选 `Cropped Area`。`Original` 忽略裁切，不会自动套用 Active Area。仅修改几何不能代替设置输出裁切。

## 重试与继续

每次重试需要明确假设及有意义的状态变化。对同一张/同一组相同错误，默认最多两次有依据的修复重试；仍无进展就记录具体阻碍，继续其他文件。有新证据或用户补充信息后可以恢复，不把次数当成算法阈值。

若后端/界面无响应，先查看最新状态与截图，区分正常队列耗时和真正无进展，保留错误及最近检查点。需要关闭 App、丢弃未保存状态、批量清缓存或更换安装包才能继续时，先保存可保留的结果并说明具体原因，不把这类动作当常规修复。
