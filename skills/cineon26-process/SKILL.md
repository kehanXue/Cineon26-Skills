# Cineon26 胶片批处理

操作基准：Cineon26 0.5.0（129）。其他版本先核对实际界面。需要能操作原生 macOS App 的 Computer Use 工具；没有该能力时说明缺失项，不以命令行后端冒充 App 操作。

## 从当前阶段继续

- **新文件夹**：读取 [workflows.md](references/workflows.md)，完成导入、初步校色、逐帧检查和必要修复。
- **已有项目**：先读取现场选择、队列、提示和当前编辑，只继续未完成工作；错误与编辑操作见 [recovery.md](references/recovery.md)。
- **保存交接或导出**：读取 [delivery.md](references/delivery.md)。默认保存后提示用户检查打分；收到明确导出要求后，按项目最新评分与编辑执行。

用户给出文件夹，已授权本次导入、分帧确认、初步校色、修框及保存新项目。不自行评分或删除取舍；不提前导出。用户明确指定的处理范围、设置及已有授权优先。

## 现场与来源

1. 核对 App 路径与版本、当前项目、未保存工作和处理队列。默认使用 `/Applications/Cineon26.app`，用户指定其他路径时遵照。通过正常保存保护已有工作，不关闭忙碌会话或替换安装包。
2. 清点授权文件夹及其相关子目录，区分原片、平场参考、重复来源和不支持项。记录路径和大小即可开始；仅在辨认同名文件、排查来源变化或需要字节一致性证明时计算哈希。不能把输入文件数、分帧照片数和导出数混为一谈。
3. 自然理解目录名、父子目录和对话中的胶卷与画幅信息，不要求固定命名格式。信息足够就继续；只对仍不确定的文件夹询问缺失项，复用已确认声明。同目录不自动等于同卷，也不能从画面颜色猜胶卷型号。
4. 按胶卷、画幅、输入类型和拍摄方式分批。导入页可能沿用已有选择，每批重新核对 Film、Frame Format、白光／三色及自动处理开关。彩色 3F 缺 ICC 时按 workflows 的指定来源下载并在 App 导入。

## 导入到可检查状态

- 先导入完整图像，有多画面时按需分帧。检查真实条数、帧数和分隔线；自动识别只是建议。已处理整图的子帧继承可用色彩，分帧本身不代表逐帧运行了 Auto。
- 默认使用 Auto Color 初步处理。检查实际选中照片数量，等待本次队列完成，再看失败项及恢复提示，避免重复提交。参数复制仅在用户希望复用编辑时使用，不能替代默认的逐张自动校色。
- 每张照片查看完整画面，视野不完整时用 Fit；核对方向、完整画面、片基、裁切与实际颜色；疑似截断、手修或颜色异常再放大检查。缩略图或旧预览不证明最新处理成功。
- 明显偏色先核对胶片声明与识别区域，再使用可用的 Color Balance；已有用户中性参考和强度要保留。场景灯光与自然色调不一律中和；纯片基片段不反复精细校色。深度校正、手动中性点和复制参数的适用范围见 recovery。
- 识别区域用于处理取样，Crop 用于构图，两者分别复核。实际改框后按提示重新自动校色；恢复已保存结果时不要无故重跑 Auto 覆盖用户手调。
- 完成全部可处理项后保存，列出具体例外并提示“可以开始检查和打分了”。用户审片后继续同一工程，不能用旧任务记录覆盖其新评分和编辑。

## 操作约束与断点

- UI 操作使用 Computer Use。依据新 AX 状态选择控件；画面、分隔线与拖动边界看截图。切图、缩放、平移或窗口变化后重新取坐标。文件选择器与批量操作均核对实际选中项。
- 文件工具可清点来源、普通下载、校验输出及维护任务记录；不直接修改工程、偏好或产品缓存，不调用内部后端代替界面修复。
- 项目和衍生物放在用户指定位置，或另建与原片分开的任务输出目录。保留原片和现有工程；测试升级使用独立项目或副本。
- 长批次分段保存、检查剩余空间与 App 缓存占用。清理需有用户授权，且核对当前、其他或全部项目的实际范围；不要为一个失败项清空全局缓存。恢复步骤见 recovery。
- 在任务目录保留足以续接的简短记录：App 版本、项目路径、输入范围及声明、已完成/未解决项、当前阶段、实际导出设置和输出。只有多画面或三色任务才增加条号、帧号或完整来源组，不强制复杂日志结构。
- 中断后先核对工程和现有输出，只继续缺失步骤。重试须有新的依据或状态变化；错误未变且没有可行恢复动作时记录并继续其他来源，不循环点击。

初步处理不等于用户已审片，也不等于科学色彩校准。报告实际完成范围；不修改 Cineon26 源码、算法或原片来消除错误。
