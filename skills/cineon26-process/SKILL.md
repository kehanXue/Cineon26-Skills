# Cineon26 胶片批处理

充当软件操作员，按两段工作流协作：“文件夹 → 全量导入与初步校色、复核修复 → 保存并提示用户检查打分”，以及“用户给出导出要求 → 读取最新评分与编辑 → 导出并核验”。默认先完成第一段，交接后等待用户回来，不提前索取导出设置或自行打分。以实际界面、照片内容和落盘文件判断完成。使用已安装 App 实际提供的功能，不假设其他版本有相同控件。

## 开始工作

- 从本轮请求和已有对话取得输入文件夹、目标 App、已知胶卷/画幅、拍摄方式及输出要求。缺少输入路径时先询问；不要擅自挑选其他私人文件夹或仓库样本执行批处理。
- 用户要求处理文件夹，已授权在这个任务内导入、复核分帧、修正几何、重新处理、保存新项目；导出需要用户明确要求。对有充分图像证据的常规操作自行完成。不要每张照片重复求确认。
- 用自然语言理解文件夹名称及目录上下文，判断胶卷型号和实际画幅，见 [workflows.md](references/workflows.md) 的“理解文件夹名称”。不规定命名模板、字段顺序或分隔符，不因名称少写某一项就机械追问。已有信息足够明确就直接处理；只有仍有实质歧义或信息不足时才按文件夹询问，并复用已确认的信息。
- 3F 批次先检查所需扫描输入 ICC。缺失、失效或无法定位时，按 [workflows.md](references/workflows.md) 的 ICC 恢复流程，从用户指定的 [Flextight-X5-ICC 仓库](https://github.com/kehanXue/Flextight-X5-ICC) 下载对应文件并通过 App 设置导入；下载和导入属于本 Skill 的常规恢复流程；用户另有指定时遵照其要求。已有有效配置则继续使用。
- 按胶卷型号、画幅、来源类型、拍摄模式分组。一个导入批次共用 Film 和 Frame Format；同一文件夹不等于同一卷。先处理已明确的组，只暂缓仍无法可靠判断的目录或混合内容中尚未确认的文件。
- 没有另行要求时，采用 App 的常规 Auto Color。RAW 结果出现明显偏色（不限于偏紫）时，核对类型与几何后可直接启用 Color Balance，按 [recovery.md](references/recovery.md) 复查效果；这是已授权的常规处理。保留当前 Post-processing 设置，不将同一组调色参数统一套用到所有照片。默认不导出图片，完成处理后保存可继续编辑的项目，明确提示用户可以检查、打分，并停止本轮操作。用户检查后给出导出要求时，再确定导出范围、格式、尺寸、色彩空间、输出位置及去边或保留片边要求；遵照其设置，不沿用未知的历史导出目标。
- 输出放在用户指定位置，或为本次任务新建、与原片目录分离的 `Cineon26 Output/<批次名>/`。项目、日志及用户要求的成片都放在那里；不往源目录写入衍生物。遵守当前文件访问权限。

## 工具与现场状态

需要 macOS、可用的 Cineon26，以及支持原生 App 的 Computer Use 工具。可使用环境提供的 `mcp__cua_repl` 等原生 App 操作工具；没有该能力时说明缺失项，不声称已操作软件。Skill 本身不提供鼠标权限，也不绕过 App 的编辑权益。

按用户指定的 App 路径操作；没有指定时先确认 `/Applications/Cineon26.app`。遵守 Computer Use 工具的初始化规则，先读取工具提供的操作文档，再进行界面操作。

- 先核实窗口、项目、选择范围、队列和弹窗。保护已有未保存工作；切换项目时走正常保存流程，无法安全保留才询问。不要退出正在处理的会话。
- 用最新 AX 树定位按钮、字段和菜单；绘制画框前查看当前截图。每次操作后重新读取状态，再决定下一步。缩放、滚动、改变窗口或切图后重新获取坐标，不复用旧屏幕位置或元素序号。
- 原生画布可通过截图定位边/角/框内，用 `drag` 修改并复核。先 Fit 看整体，必要时放大检查边界。AX 不包含画面内容时必须看图，不能仅凭“Ready”判定画框正确。
- 文件选择器的“前往文件夹”打开后，先读取新弹窗，再填完整路径并核对选中的文件。保存对话框填写名称后离开字段，让界面完成校验，再检查 Save 是否可用；输入动作成功不等于已保存。
- 界面动作通过 Computer Use 完成。终端可用于只读文件清点、源文件哈希和导出核验；不直接改工程、缓存或 App 配置来绕过界面校验，不用命令行图像处理替代 GUI 操作。
- 启动初期的权益和控件可能仍在刷新，先重新读取实际状态再判断阻碍。持续出现试用、购买、登录、系统授权或只读状态时，如实记录，交给用户处理所需的账户或权限步骤。继续可以完成的清点工作，不改收据、权益、签名或安全设置。

## 执行与检查点

1. 清点授权范围内的文件。记录相对路径、字节数及 SHA-256，识别候选 RAW/3F、参考图与不支持项；扩展名只是候选类型，App 探测结果才决定支持情况。记录子文件夹是否纳入，避免把同一来源重复导入。
2. 按 [workflows.md](references/workflows.md) 的“理解文件夹名称”和“输入判断”，综合名称、上下文及可靠记录确定 Film、Frame Format 和拍摄模式，只读取本次涉及的 RAW、3F 或 RGB 分支。能可靠判断就继续；仍不明确时按目录询问，不凭外观猜型号或沿用上次导入设置。
3. 为本次任务使用明确的项目，尽早保存到输出目录。按照分组导入授权范围内全部可用来源，核对候选、跳过和成功数；除非用户指定抽样，不以代表样本代替整批。无法导入的项保留原因。3F 经视觉复核后在 App 内确认；用户要求代操作时，这一步由你完成。
4. 选中明确的一批可处理照片，运行顶部 Auto Color。等待队列实际结束；反复点击会影响优先级，不以重复提交代替等待。对当前选择的有效范围做检查，避免同时处理未完成复核的照片。
5. 逐张检查处理状态、方向、画框、负片片基及成片。每张至少查看 Fit；人工修复、疑似截断、RGB 重影或异常颜色的照片再检查真实 100%。新输入分组先检查一张结果，随后批量处理；末尾仍逐张核对。 经查看确认只有片基、没有实际画面的截取，记录为 `blank_film_base` 并跳过细致校色，不反复修框或调色求通过；保留项目中的记录，评分与取舍留给用户。有暗部图像或只是带长段片基的照片仍按实际画面检查，不能只凭黑色缩略图判为空白。
6. 遇到失败，读详情再按 [recovery.md](references/recovery.md) 判断修复层级。修改几何或上游设置后重新 Auto，并确认新的有效结果；旧预览仍可见不代表成功。无图像证据时不挪框凑通过、不改算法阈值。
7. 按 [delivery.md](references/delivery.md) 核验并保存项目，交付可继续编辑的项目和准确的异常清单，明确提示“可以开始检查、打分了”。将本次任务阶段记为 `awaiting_user_review`，结束本轮操作，评分和取舍留给用户。复核所有原片哈希；未完成字节校验时不得声称“原片逐字节未变”。
8. 用户检查后给出导出指令时，从同一项目接续，按 [delivery.md](references/delivery.md) 读取最新评分、选择和编辑，执行导出并核验成片。保留用户的调色、裁切和评分；不重新导入或仅为导出重跑整批 Auto。指令清楚就执行，不额外索取一次重复批准。

在输出目录维护简短的 `processing-log.json`，至少记录 App 路径/版本、来源清单、分组依据、项目路径、逐帧状态和修复、导出路径、未解决原因。用 `folder_declarations` 记录目录、已确认文件范围、Film/Frame Format 及声明来源，恢复任务时复用仍适用的确认。任务阶段单独记录，区分前置处理、`awaiting_user_review` 和按要求导出；交接时记录项目路径、可检查数和未解决项，导出时记录实际评分/选择范围及输出设置。3F 用“来源文件 + 确认的帧序号”标识，RGB 用完整源文件组标识。记录状态可以是 `imported`、`review`、`processing`、`ready`、`exported`、`blocked`；只有实际核验后的输出可记为 `exported`。

在导入、分帧、修复及导出完成后更新日志并保存项目。恢复中断任务先核对项目与落盘文件，继续未完成项；不重新导入整卷，不把重复导出的副本算作新照片。运行时的输入数、照片数和导出数分别统计，不能假设三者相等。

## 完成标准与边界

- 自动修正只依据原片内容、真实边界和错误原因；不以第三方成片为目标拟合，不修改 Cineon26 的实现或处理逻辑。
- 拍摄缺失、严重过曝/欠曝、真实片基不可用、无法确认胶卷、不同帧被误配或文件损坏，可能需要用户补充信息或重拍。标出具体组，完成其他可处理项目。
- 第一段完成时报告可检查数量、修复、未解决项与项目位置，并提示用户开始检查打分；部分完成时说明具体范围。第二段完成时报告实际导出数量、设置、输出位置与失败项。初步处理完成不代表用户已审片或评分；导出成功也不等于科学色彩校准。

Skill 结构遵循 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。本技能运行依赖 Computer Use，无额外 Python 包、独立后台服务或固定分辨率点击脚本。
