# Cineon26 胶片批处理

按两段流程操作：“文件夹 → 导入、初步校色与修框 → 保存并交给用户检查打分”；“用户给出导出要求 → 读取最新评分与编辑 → 导出并核验”。默认完成第一段后结束本轮，不自行打分、不提前导出。操作说明以 Cineon26 0.5.0（120）为基准；其他版本先核对实际界面，不能把本文当作功能存在的证明。

## 开始工作

- 从请求和已有对话取得输入路径、已知胶卷与画幅、拍摄方式和项目位置。缺少路径才询问，不擅自挑其他私人目录或开发样本。
- 自然理解目录名、父子目录和用户说明，不规定命名模板。信息足够就继续；仅对仍有歧义的文件夹合并询问缺失信息，复用已经确认的声明。见 [workflows.md](references/workflows.md)。
- 按来源、胶卷、画幅、拍摄模式和是否需要分帧分批；同目录不自动等于同卷。每批核对 Film、Frame Format 及导入开关，不沿用未知历史值。
- 用户要求处理文件夹，已授权该任务内导入、确认分帧、初步校色、修框和保存新项目。导出仅按明确要求。3F 缺失所需 ICC 时，按 [workflows.md](references/workflows.md) 从指定公共仓库下载并通过 App 设置导入。
- 用常规 Auto Color 初步处理。彩色 RAW 明显偏色时，核对类型和画框后可启用 Color Balance；彩色 3F 使用独立色彩平衡，按需启用。黑白负片选择对应型号，使用明暗调整，不尝试开启被禁用的色彩控件。保留场景原有色调和用户指定设置，不将一张图的参数复制给整批。仅有片基而无画面的片段不细致校色，留给用户取舍。
- 项目与任务日志放在用户指定位置，或另建与原片目录分离的 `Cineon26 Output/<批次名>/`。不要往原片旁写衍生物。

## 工具与现场状态

需要 macOS、可用的 Cineon26 和能操作原生 App 的 Computer Use 工具（如 `mcp__cua_repl`）。没有该能力就说明缺失项，不声称已操作。按工具初始化文档使用；默认核对 `/Applications/Cineon26.app` 的实际版本及窗口，用户指定路径时遵照。

- 先检查项目、未保存工作、选择范围、队列与弹窗。通过正常保存流程保护已有工作，不关闭忙碌会话，不用开发包替换用户安装。
- 依据最新 AX 树操作菜单；画布内容与边界必须看截图。每次操作后刷新状态；切图、缩放、平移或窗口变化后重新取得坐标。不要用固定坐标脚本跑整批。
- 120 的直方图固定在调整栏顶部，下方参数独立滚动。根据按钮帮助文字区分 Auto、画框、裁切与面板显隐，不只依赖自动化工具返回的图标名称。
- 文件选择器打开“前往文件夹”后先读取新状态，再填写完整路径，核对真实选中项。保存时确认目录和名称、按钮校验及落盘结果，不能把输入成功视为保存成功。
- 界面操作通过 Computer Use。终端只用于文件清点、校验、普通下载及导出核验，不直接改工程、缓存、偏好设置或调用产品后端代替 GUI。
- 启动后的内测权限可能仍在刷新。先等待状态更新；若提示联网，可用 App 的检查内测权限操作。账户、购买或系统授权问题按实际提示处理，不改收据、权益或安全设置。

## 执行流程

1. 清点授权目录，记录相对路径、大小及源文件 SHA-256；区分原片、平场参考和不支持项。扩展名仅供筛选，App 探测决定兼容性。明确是否递归子目录，避免重复导入。
2. 按 [workflows.md](references/workflows.md) 确认分组与 Film/Frame Format。只含一张胶片画面的文件用单帧导入；一张原图包含多张画面时勾选多画面选项。RAW、兼容线性 DNG／TIFF 与 3F 都适用，不能仅凭扩展名决定分帧。
3. 尽早保存本次项目。全量导入授权来源，检查条带方向、条数、每条帧数与分隔线后确认；自动识别只是建议。对照来源清单核对导入、跳过和失败项，不以抽样代替整批。
4. 核对“导入后立即开始自动批量处理”，或分帧页的“确认分帧后立即开始自动批量处理”。已开启就等待新批次完成，不再次提交同一批 Auto。关闭时先复核，再明确选择待处理照片运行 Auto Color（Command-L）。单张失败不代表整批失败，读取最终汇总和各卡片状态。
5. 逐张检查方向、画框、负片片基与成片，每张至少看 Fit；修复、疑似截断或异常颜色再看 100%。新来源先检查一张，再继续批量。确认是纯片基的记录为 `blank_film_base`，不反复调色求通过；不能只凭黑色缩略图判空白。
6. 需要修复时读具体错误与下一步，按 [recovery.md](references/recovery.md) 操作。画框有效且内容正确时可直接 Auto 确认，无需先挪一下；实际修改区域后用“重新自动校色”应用。G/D 显示画框会临时展开完整图片，隐藏后恢复裁切；几何角点默认自由调整矩形，按住 Shift 保持比例。旧预览仍显示不证明新处理成功。
7. 按 [delivery.md](references/delivery.md) 保存、核对队列和全部来源去向，提示“可以开始检查、打分了”，给出项目位置及例外；阶段记为 `awaiting_user_review`，结束本轮。保留已有评分与用户编辑。
8. 收到导出要求后从同一项目接续，读取最新评分、裁切、调色与范围；按 [delivery.md](references/delivery.md) 选择 SDR 或 HDR 设置并核验文件。不要恢复旧日志覆盖用户编辑，不为导出重跑整批 Auto。

在任务输出目录维护简短 `processing-log.json`：App 路径/版本、来源清单、目录声明及依据、项目位置、每帧状态/修复、当前阶段、未解决原因、用户要求的导出范围/设置/实际输出。多画面用“来源 + 条号 + 帧号”标识，RGB 用完整来源组标识。输入文件数、创建照片数与导出数分别统计。导入、分帧、修复和导出后保存检查点；中断恢复先核对项目与已存在输出，只继续未完成项。

## 边界

修正依据原片内容和真实错误，不修改 Cineon26 源码或算法，不以第三方成片拟合结果。真实片基不可用、损坏文件、缺失曝光或型号未明可能无法自动解决；说明具体范围，继续其他可处理项。

第一段报告可检查范围、未解决项和项目位置；第二段报告实际输出、设置、失败项。只有前后哈希核对后才称原片逐字节未变。初步校色完成不代表用户已审片，也不代表科学色彩校准。
